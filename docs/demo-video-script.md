# 工业品导购 Agent · 3 分钟演示视频脚本

> 用途：简历项目演示 / 面试自述素材。目标 3 分钟，不超过 3 分 20 秒。
> 原则：先讲痛点，再演效果，最后讲设计——面试官关心「你为什么这么做」，不是「你做了个聊天框」。

## 一、录制前准备（5 分钟）

**环境**

1. 后端、前端都起好，浏览器打开 `http://localhost:5200`，确认页面能出示例问句。
2. **先热一次 LLM**：随便问一句「24V 开关电源 10 个」，等它出结果。DeepSeek 首次调用可能要 3-5 秒，冷启动直接录会有一段干等。
3. 浏览器缩放到 **125%**（问题字大、卡片清楚），窗口 1440×900 左右；关掉书签栏、扩展图标、其他标签页。
4. 桌面通知全部静音（Win+A 打开专注助手）。

**录制工具**（任选）

- Xbox Game Bar：`Win + G` → 捕获 → 录制（默认录全屏或当前窗口）
- OBS：录浏览器窗口，1080p 30fps 足够
- 录完检查音轨有没有电流声，麦克风离嘴 15-20 cm

**输入方式**

问句提前复制到剪贴板，录制时 `Ctrl + V` 粘贴再回车——比现场打字快，也不容易打错字。

## 三、分段脚本

### 0:00-0:15 开场

**画面**：浏览器首页（示例问句 + 输入栏）。

**口播**：

> 大家好，这是我做的工业品导购 Agent。工业品采购有个很典型的问题：同一个 M8 螺丝，材质、长度、头型、标准能分出几十个 SKU，采购人员在目录里一级级点筛选，效率很低。我想做的是——用一句话说清需求，直接拿到可下单的清单。

**动作**：不操作，让镜头停在首页。

### 0:15-0:45 演示 1：完整需求

**动作**：粘贴并发送 `304 不锈钢 M8×30 内六角螺丝，要 1000 个`。

**口播**（等结果时就说）：

> 这句里有品类、材质、规格、数量四类信息，系统会先判断这是采购意图，再抽取参数，走混合检索。

**结果出来后**（指着卡片）：

> 返回的是结构化商品卡片：型号、品牌、单价、起订量、交期，还有一段推荐理由——它会告诉我哪个最匹配、为什么，以及数量够不够起订量。

### 0:45-1:15 演示 2：缺参追问

**动作**：发送 `我要买螺丝`。

**口播**：

> 如果信息不全呢？我只说「我要买螺丝」，它不会返回一堆无关结果，而是先追问缺的那一项——螺纹规格。

**等追问出现后**（念一遍追问文案），再发送 `M8 的螺丝，1000 个`。

**口播**：

> 补上规格和数量，就正常出清单了。这里只问真正缺的字段：紧固件缺螺纹规格就问 M 号，轴承缺内径就问内径，不会一口气让用户填五张表。

> 补充说明（可选，若时间富余）：目前是单轮对话，第二轮需要带上品类词，多轮上下文合并是下一步要做的。

### 1:15-1:45 演示 3：MOQ 校验

**动作**：发送 `内径 20 的轴承要 50 个`。

**口播**（结果出来前）：

> 这一条是真实采购里最容易踩坑的地方——起订量。

**结果出来后**：

> 内径 20mm 的普通深沟球轴承起订量是 100 个，我要 50 个不够；系统在推荐里直接点出来，并优先给了起订量 50 的陶瓷轴承。这种「参数对得上但买不了」的情况，纯关键词搜索是发现不了的。

### 1:45-2:05 演示 4：闲聊不跑偏

**动作**：发送 `螺丝和螺栓有什么区别`。

**口播**：

> 用户不一定每句话都是下单。问一句常识问题，它按知识问答回应，答完再把话题拉回采购，而不是硬塞一堆商品。

**结果出来后**：

> 之前这版会被当成「缺参数」反复追问品类，后来加了意图判断这一层才修好。

### 2:05-2:45 技术讲解

**动作**：切到 README 的架构图（浏览器新标签打开仓库 README，或直接把 mermaid 图截图放旁边）。

**口播**：

> 技术上分五层。
>
> 第一层意图判断：先用规则和词表分流——有品类词、又带参数或购买词，就是采购；问「是什么、怎么选」就是知识；判不出来才调一次 LLM，8 个 token 就够。这样大多数请求不过模型，又快又省。
>
> 第二层需求解析：正则抽出品类、材质、规格、数量，同时把短查询改写成完整 query，弥补语义缺失。
>
> 第三层检索：向量用 bge-m3 加 FAISS，关键词用 jieba 加 BM25，两路用 RRF 融合——因为两种分数量纲不同，RRF 只看排名，免调权重。融合后再做参数硬过滤，M8 就是 M8，不会把 M10 排前面。
>
> 第四层生成：把候选商品拼成编号列表交给 DeepSeek，让它排序、给理由、校验起订量。模型挂了会回退到模板，保证一定出清单。
>
> 第五层是展示，前端只负责渲染卡片。

**提示**：这段信息密度最高，语速放慢，每层一句话就够，不要背稿。

### 2:45-3:00 收尾

**动作**：回到首页，或停在最后一张结果卡片。

**口播**：

> 目前的限制是数据只有三个品类 45 条种子商品，参数抽取也是规则覆盖，还没到真实目录的规模。下一步想做多轮对话，把追问补的参数合并进上一轮，然后接真实商品源，验证万级 SKU 下的检索质量。
>
> 代码和 README 都在这——谢谢观看。

## 四、防翻车备选

| 风险 | 处理 |
| --- | --- |
| LLM 响应慢，画面干等 | 录制前先热一次；等待时说口播词，不要沉默 |
| 追问文案每次不一样 | 正常现象，别重录；口播说「它会追问缺的规格」即可，不要逐字念 |
| 演示 2 补全后识别成别的品类 | 一定用 `M8 的螺丝，1000 个`（带品类词）；不要用 `M8 的，1000 个`，单轮系统会再问一次品类 |
| 推荐里候选编号与卡片顺序不完全一致 | 讲解时以卡片为准，说「第一张卡片」而不是「候选 1」 |
| 网络断、接口报错 | 把 10 条问句提前在另一个标签页跑通一次；真出错就重录这一段，剪辑拼接 |
