## 4. Excel 上传：3 个表

点输入框左边的回形针选文件（收 `.xlsx` / `.xlsm` 和图片）。三个表都已实测：

| 表 | 内容 | 期望 |
| --- | --- | --- |
| 标准表 | 表头「物料名称 / 规格型号 / 材质 / 数量 / 单位」，5 行数据 + 一行合计 | `header_row=1`，识别 5 行，扳手那行标「库外」，合计行被跳过 |
| 无表头 | 直接三列数据 | `fallback=true`，按「第一列品名、第二列规格」猜，2 行都能匹配 |
| 怪列名 | 「存货名称 / 产品型号 / 采购数量 / 计量单位 / 品牌」 | 表头识别正确，交流接触器、陶瓷轴承都匹配到 |

要点：

- `M8×30` 会同时抽出螺纹规格和长度，长度不符的 M8×50 会被过滤掉；只写「M8」不写长度时不过滤
- 合计行、空行、备注行自动跳过，返回里的 `skipped` 能看到跳了几行
- 数量低于起订量标「低于起订量」，不是静默放过
- 只写规格不写长度（比如「内六角螺栓 M8×30」写全了没事，只写「内六角螺栓 M8」）时标「缺参数」并提示「暂不可下单」，不会假装可下单
- 每行判断来自后端 `evaluate_row()`，刷新后重新打开会话，同一行的标签必须和刚上传时一致

## 6. 会话：4 个动作

1. **刷新不丢**：发两轮对话，按 F5，消息还在，侧栏那条会话仍是选中态
2. **开新对话**：点左上「新对话」，输入区变空，侧栏多出一条；跟新会话说句话，切回旧会话，两边内容不串
3. **切回旧会话**：点侧栏里的旧会话，消息和商品卡片都回来（表格类附件也能回来）
4. **删除会话**：悬停会话条目，点右侧叉号，条目消失；删的是当前会话时自动跳到最近一条

要点：

- 会话存在后端 SQLite（`sessions` / `messages` 表），不是浏览器缓存，换标签页也一致
- 新建出来的会话标题是「新对话」，发出第一条消息后自动变成那句话的前 20 字
- 侧栏条目按最近更新时间倒序，刚聊过的排最上面

## 7. 评价：2 个动作

1. **点赞**：助手回复下面有一对图标，点 👍 变蓝并出现「收到，谢谢」；刷新页面回来，状态还在（评价存在后端，不在浏览器里）

## 8. 接口层抽查（可选，讲技术时用）

```powershell
# 单轮
$q = [uri]::EscapeDataString('304 不锈钢 M8 螺丝 1000 个')
```

## 9. 已知小瑕疵（照实说，别辩解）

- 推荐文本里 LLM 偶尔用「候选 1/候选 2」指代商品，和前端卡片顺序不完全一致——不影响下单信息，卡片本身是准的。
- 多轮回放最近 8 条消息，更早的不参与；会话已落库，但没账号体系，所有人共用同一个库。
- 追问设计成一次只问一个参数，但 LLM 偶发会把两个塞进一句话，换个说法重发即可，属模型波动。
- 追问按钮给的是行业标准规格，不是库存清单，点下去可能返回「没有匹配的商品」——这是正常的，标准规格该有、现货另说。
- 多需求表格每行只显示首推商品，想看完整候选得回到单需求；多行里缺参数的行不追问，直接给参考候选并标「缺参数」。
- 结果区固定显示最近一条带商品的消息；历史会话栏可以折叠成窄条（折叠状态会存下来），窗口窄于 1200px 时对话区自动收到 400px。
- 开发模式下 React StrictMode 会让初始化 effect 跑两次，容易多建一条空会话；已经用 ref 挡住了，如果还看到多余的空会话，刷新一次即可。
- 想复现任意一条，项目根有 `.tmp_check_scope.py`、`.tmp_check_multi.py`、`.tmp_check_mem.py`、`.tmp_demo_check.py`、`.tmp_check_excel.py`、`.tmp_check_vision.py`、`.tmp_check_session.py`、`.tmp_check_final.py`、`.tmp_check_clarify.py`、`.tmp_check_feedback.py`、`.tmp_check_multirows.py`、`.tmp_check_multiturn.py`，直接跑就能看全部用例的输出。
- 评价没有账号体系，谁点都算数，只能看总量趋势；也没强制填原因，想知道「为什么差评」得回看那条对话。

## 10. 一条没过怎么办
